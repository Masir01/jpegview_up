# 2026-08-08

## SelectionZoomMode 功能实施

新增 INI 配置项 `SelectionZoomMode`，控制框选释放后行为：
- `false`（默认）: 裁剪模式 — 弹裁剪菜单
- `true`: 局部放大模式 — 框选区放大到全屏

改动 4 文件: SettingsProvider.h/.cpp, MainDlg.cpp, JPEGView.ini.tpl
编译: x64 Release 0 error 0 warning
核心逻辑: `ZoomToSelection()` 已存在，仅加一层 INI 判断的分派

## 防误触：框选最小尺寸阈值

- 在 `OnLButtonUp` 放大分支中加入阈值判断：框选宽/高 < 12 屏幕像素时回退为裁剪菜单模式
- 避免单击抖动或微量拖动导致的"单点放大"
- `CropCtl.h`: `GetScreenCropRect()` 从 private 提到 public
- 编译通过, 0 error

## 连续框选放大支持

- `OnLButtonDown` (line 772) 进入选择/框选模式的条件中加入 `|| CSettingsProvider::This().SelectionZoomMode()`
- 之前当图片>窗口且 DefaultSelectionMode=false 时，第一次 zoom 后 AbortCropping 重置状态，下一次 LButtonDown 会走拖拽分支而非框选分支
- 加入此条件后 SelectionZoomMode=true 时强制进入框选模式，实现连续框选放大
- 仅 1 行改动，编译通过 0 error

## 单点/微拖拽误出裁剪菜单修复

- 根因：`OnLButtonUp` 用 12px 判断是否 zoom，`EndCropping` 内部用 `PointDifferenceSmall`（<2px）判断是否“点一下取消”，2~12px 的微小拖拽两头不靠，就掉进了 `ShowCropContextMenu`
- 修复：`OnLButtonUp` 中当 bSelectZoom=true（Shift 或 SelectionZoomMode）且选区小于 12px 时，直接 `AbortCropping()` 静默取消，不再调用 `EndCropping(true)` 弹菜单
- 普通裁剪模式（DefaultSelectionMode，无 Shift）保持原行为不变
- 编译通过，0 error（仅仓库既有 C4090 warning）

## 框选放大上限 100%

- `ZoomToSelection()` 中，当 `Helpers::GetZoomParameters` 算出的缩放比 > 1.0 时，上限为 1.0（100% / 1:1 像素映射）
- 同时重新计算 offsets：`imageSize/2 - zoomRectCenter` 将选区居中显示
- 更高比例需用 Ctrl+滚轮（原始逻辑不变）
- 编译通过 0 error（仅仓库既有 C4090 warning）

## >=100% 时左键进入拖拽平移

- `OnLButtonDown` line 772 中 `SelectionZoomMode()` 条件加 `m_state.m_dZoom < 1.0` 门控
- 缩放 >= 100% 时跳过选区模式，自然落入 `bDraggingRequired → StartDragging` 实现拖拽平移
- 缩放 < 100% 时行为不变（框选放大）
- 编译通过 0 error（仅仓库既有 C4090 warning）
