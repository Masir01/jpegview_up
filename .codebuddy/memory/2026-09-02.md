# 2026-09-02 JPEGView JXL/AVIF 打不开排查 + 极速模式

## 极速模式（FastFitScreenDecode）
- 新增配置 `FastFitScreenDecode`（默认 false，仅 ini 键），ini.tpl 有注释。极速模式：大于屏幕的 JPEG/有损 WebP 解码期直接降到 ≤ 屏幕（保比例，两维都不超屏）。
- JPEG：TJPEGWrapper::ReadImage 加 nScreenWidth/nScreenHeight 参数；新增 FindScreenFitFactor（1/2^n 档，上限沿用 OversizedDownscaleMaxFactor=8）。lossless JPEG 不缩放。
- WebP：WEBPWrapper::ReadImage 加 pScaleDenom+screen 参数；仅 features.format==1（有损 VP8）静态图支持 libwebp use_scaling 任意比例缩放；无损/动画不缩放。缩放失败回退全尺寸。
- ImageLoadThread ProcessReadJPEGRequest/ProcessReadWEBPRequest 传 request->ProcessParams.MonitorSize，成功后 SetDownsampleFactor → 标题 [1/n]、禁保存自动沿用。
- 其它调用点（dcraw/RAW/PSD 内嵌 JPEG）用默认参数不受影响。x64 Release 编译通过 0 error（post-build MSB3073 为遗留路径告警）。

## 标题栏解码模式标识
- CJPEGImage 新增 EDownscaleReason 枚举（None/Oversized/FastFit）与 FastDecoded 标志 + 访问器；构造初始化。
- TurboJpeg::ReadImage 新增 pDownscaleType out 参数（1=oversized, 2=fastfit，0=无）；ImageLoadThread JPEG/WEBP 解码点设置 image reason/fast 标志。
- MainDlg::UpdateWindowTitle 路径后追加：`[fast]`、`[1/N fit]`、`[1/N oversized]`（ASCII 硬编码，语言无关）。
- 快速解码标识仅 JPEG（FastJPEGDecode）；RAW(FastRAWDecode) 未加。

## 双击 100% 转原图（2026-09-03 补充记录于 09-02 文件）
- 需求：极速模式下双击放大到 100% 时，JPEG 降采样预览跳回全分辨率原图。
- 实现：CProcessParams 加 DecodeFullResolution；MainDlg 新成员 m_bForceFullResolutionNextLoad（in-class init）；OnLButtonDblClk 双击到100% 分支，当 JPEG 且 factor>1 且 m_bUserZoom → GotoImage(POS_Current, KEEP_PARAMETERS|NO_REMOVE_KEY_MSG) 同步全解替换（保留 100% zoom，PerformZoom 已置 m_bUserZoom=true）；GotoImage 消费一次该标志 → ProcessReadJPEGRequest 将 monitorSize 置 0 跳过 fastfit。
- 注意：OversizedDownscaleDecode 仍兜底（超 MAX_IMAGE 图仍降采样）；JPEGProvider 缓存 key=文件名+帧号，GotoImage POS_Current 会先 ClearRequest 旧 request 再同步 RequestImage。

## 极速模式下限修复（9000px 高竖图失效）
- 现象：6034×9054（高>屏×8）在 1080p 屏极速模式失效（仍全分辨率）。原因：libjpeg-turbo 缩放下限 1/8（9054/8=1131>1080），FindScreenFitFactor 找不到精确 fit 档即返回"不缩放"。
- 修复：FindScreenFitFactor 找不到完全 fit 档时返回**最大档(1/8)**而非 TJUNSCALED；剩余少量超出由显示层 final resample 处理。标题显示 [1/8 fit]。

## 根因定案（JXL 双重释放）
- ProcessReadJXLRequest 用 `new[]` 分配 pBuffer 传给 JxlReader::DecodeJpegXlOneShot；解码器**直接持有该外部指针**（`cache.data = (uint8_t*)jxl`）不拷贝。
- 非动画 jxl：ReadImage 尾部 DeleteCache() 执行 `free(cache.data)`（跨 new[]/free 非法），随后 ProcessReadJXLRequest `delete[] pBuffer` → **同一块双重释放** → 堆 free-list 损坏 → 后续任意 free（如 delete rq.Image）触发 AVRF/ntdll 堆崩溃，进程 3 秒无 UI 退出。
- 动画 jxl：cache.data 悬垂（外部缓冲已 delete）→ 次帧 Rewind/SetInput UAF。
- 与上游 d7cd949 "actually fix the double free"（修 AVIF）同源缺陷模式。
- AVIF cache.data 是 malloc+memcpy 内部拷贝故安全；avif 崩溃疑与 jxl 污染堆的连带或同现场，待复测。
