## 从 JPEGView_L 借鉴的纯优化（2026-09-13 下午）

### 调研结论（对比 JPEGView_L-1.4.0.5，逐文件 diff）
- 两者是**不同实现路线**，不是"L 领先"：
  - L：float32 SIMD kernel（`_mm256_mul_ps`，8 float/寄存器）+ 线性光空间 + `LinRGB12_sRGB8[4096]` 查表；StripPadding 8/4；ALIGN 32/64。
  - 本 fork：**int16 定点 SIMD**（`_mm256_mulhi_epi16`，16 short/寄存器，每指令 2 倍像素吞吐）；移位转换 `(px+42)>>6` 而非查表；ALIGN 16/32。
  - 结论：L 的热路径**无实质提速可捡**，其 float 路线是为线性光画质服务（会改变画面明暗，非纯优化）。
- L 优势项多为功能：多下采样滤镜（Hermite/Mitchell/Catrom/Lanczos2）、线性光、CacheRange、书签/漫画包等；JXL 的 `CountJxlFrames()` 反而多一次全解码扫描。
- 本 fork 已领先：HEIF 已用 C API + `num_codec_threads`（L 仍旧 C++ API 无多线程）；JXL 已修双重释放；BasicProcessing 有大图 `(size_t)` 溢出保护；JPEG 有降采样解码。

### 已实施改动（2 项）
1. `AVIFWrapper.cpp`：`avifDecoderCreate()` 返回值判空 → `DeleteCache(); outOfMemory=true; return NULL;`（原先会在 `cache.decoder->maxThreads` 空指针崩溃）。
2. `ImageLoadThread.cpp` JPEG ICC 改由 lcms2 处理（不再为 ICC 走 GDI+）：
   - 新增 static `ExtractJPEGICCProfile()`（APP2 `ICC_PROFILE\0` 段解析，按 chunk 序号拼接多块，需 ≥128 字节）。
   - `bUseGDIPlus` 由 `ForceGDIPlus() || UseEmbeddedColorProfiles()` 改为**仅 `ForceGDIPlus()`**。
   - TurboJPEG 成功分支（nBPP==3 且 `UseEmbeddedColorProfiles()`）原地变换：`ICCProfileTransform::CreateTransform(icc, size, FORMAT_BGR)` + `DoTransform(pixels, pixels, w, h, Helpers::DoPadding(w*3,4))`。
   - 头部新增 `#include <vector>` / `#include "ICCProfileTransform.h"`。
   - 关键前提：TurboJPEG 输出 `TJPF_BGR` 且行 pitch = `TJPAD(w*3)`，与 `FORMAT_BGR` + padded stride 完全匹配；lcms2 原地变换已有 AVIF 先例。
- 收益：开启 ICC 时 JPEG 仍走 TurboJPEG（含降采样解码/极速模式），此前该类图会被 GDI+ 全量解码绕过。
- **注意**：`UseEmbeddedColorProfiles` 默认 **false**（SettingsProvider.cpp:214），故新路径默认不触发，默认行为零变化。

## JXL 动画帧数修复（2026-09-13 下午，第 2 批）

### 问题（真 bug，非"锦上添花"）
- 原实现 `frame_count = 2`（占位）。`Helpers.cpp:864-895 GetFrameIndex()` 用 `NumberOfFrames()` 做回绕判定：
  `if (isAnimation && bPlayAnimation) { if (nFrameIndex > NumberOfFrames()-1) nFrameIndex = 0; }`
- 于是动画 jxl **只在第 0/1 帧之间循环，第 3 帧起永不显示**（且因 JPEGProvider 会命中已缓存的 FrameIndex=0/1 请求，解码器不再被推进）。
- 旁证：JPEGView_L 1.4.0.5 changelog 第一条即 "Fixed jxl animation issue"。
- 机制补充：JXL 动画靠**连续调用同一个 decoder 推进**（`ReadImage` 签名里没有 frame_index），`JXL_DEC_SUCCESS` 时 rewind 重新订阅 `FRAME|FULL_IMAGE` 实现循环。

### 修复（JXLWrapper.cpp）
- `jxl_cache` 新增 `int total_frames;`（0 = 未确定；`DeleteCache()` 的 `cache = {0}` 自动清零）。
- 新增静态 `CountJxlFrames()`：临时 decoder，**只订阅 `JXL_DEC_FRAME`**（不解像素），循环 `JxlDecoderProcessInput` 计数，遇 `SUCCESS/ERROR/NEED_MORE_INPUT` 结束；失败返回 0。
- `have_animation` 分支：`cache.total_frames <= 0` 时扫描一次并缓存；`frame_count = cache.total_frames`；扫描失败回退 `2`（保持旧行为，避免退化成"单帧不播"）。
- 编译：x64 Release exit=0，新增 exe。

### 验证方式
- 动画 jxl 无帧数元数据，`GetMultiframeIndex()` 只对非动画多帧显示 `[a/b]`，标题栏看不到帧数 → 只能靠**观感验证**（动画应播完整轮次，而非两帧抖动）。

## 新增可选项：线性光重采样（LinearLightResampling，2026-09-13 下午第 3 批）

参考 JPEGView_L 的 float32 + 线性光实现，做成**默认关闭的 INI 开关**（`LinearLightResampling=false`），默认路径与行为完全不变。

### 关键机制（为何可行）
- L 与我们的 SIMD kernel 容器**字节布局完全相同**：`XMMKernelElement::valueRepeated[8]`(int16)=16B=4 floats；`AVXKernelElement::valueRepeated[16]`(int16)=32B=8 floats。L 只是按 float 解释同一块内存并把 `CXMMImage::GetLineSize()` 从 `*2` 改成 `*4`。
- 因此可以用**运行时开关**在同一条管线里分派，无需两套类。

### 改动清单
- 新增 `src/JPEGView/LookupTables.h`（从 L 复制）：`sRGB8_LinRGB12[256]`、`LinRGB12_sRGB8[4096]`。
- `XMMImage.h/.cpp`：新增 `m_bLinear`（Init 中最先赋值，供 GetMemSize 使用）；`GetLineSize()` = `m_nPaddedWidth * (m_bLinear ? 4 : 2)`；DIB→内存构造时线性分支用 `sRGB8_LinRGB12[]` 存 float（并把 `nFirstY*nSrcLineWidthPadded` 改为 `(long long)` 防溢出）；`ConvertToDIBRGBA()` 线性分支用 `LinRGB12_sRGB8[]` 还原 8bit。
- `ResizeFilter.h/.cpp`：新增 `m_bLinear`（构造时记录）；XMM/AVX kernel 填充按模式写 float（4/8 个，值 = Kernel/FP_ONE）或 int16（8/16 个）；`ParametersMatch` 加入 `m_bLinear == 当前设置` 参与匹配，避免模式切换复用错 kernel。
- `ApplyFilterAVX.h/.cpp`：新增 `ApplyFilter_AVX_Linear(..., bool bRoundResult)`：`_mm256_mul_ps` 内积，bRoundResult 时 clamp 到 [0,4095] 并 `_mm256_round_ps`；8 floats/寄存器 → 每块 8 像素。
- `BasicProcessing.cpp`：新增 float 版辅助函数 `RotateLineLinear/RotateLineToDIB_1Linear/RotateLineToDIBLinear/RotateBlockLinear/RotateBlockToDIBLinear/RotateLinear/RotateToDIBLinear`（输出用 `ALPHA_OPAQUE | LinRGB12_sRGB8[...]`，注意 DIB_1 写 uint32 以补 alpha，比 L 更稳）；`SampleUp/Down_HQ_AVX_Core` 内 `bLinear` 分派（padding/寄存器像素数 16→8）；`SampleUp/Down_HQ_SIMD` 的 padding `(AVX2 ? (bLinear?8:16) : 8)`；`CRequestUpDownSampling` 的 StripPadding 在线性+AVX2 时减半（16→8）。
- `SettingsProvider.h/.cpp` + `Config/JPEGView.ini.tpl`：新增 `LinearLightResampling`。**仅在 `_WIN64` 且 `m_eCPUAlgorithm == Helpers::CPU_AVX2` 时生效**（否则强制 false，避免 SSE/标量路径拿到 float kernel 而错乱）。
