# 2026-09-20 动画格式支持现状调研（AVIF / HEIC-HEIF）

## 结论
- **AVIF 动画：已支持**（代码路径完整）。
- **HEIC/HEIF 动画：不支持**，打开后只显示主图（首帧）静态画面。
- libheif 1.23.1 **已具备**序列解码 API（`heif_sequences.h`），不需要升级库。

## 依据（代码事实）
### AVIF（`AVIFWrapper.cpp` + `ImageLoadThread.cpp:976-991`）
- `has_animation = cache.decoder->imageCount > 1`；`frame_count = decoder->imageCount`；`frame_time = imageTiming.duration*1000`。
- 逐帧 `avifDecoderNthImage(cache.decoder, frame_index)`，动画时保留 decoder 缓存（`m_sLastAvifFileName` 复用），非动画才 `DeleteCache()`。
- 帧数由 libavif 直接提供 → 无需预扫描（比 JXL/HEIF 友好）。

### HEIF/HEIC（`HEIFWrapper.cpp` + `ImageLoadThread.cpp:1033-1042`）
- `frame_count = context.get_number_of_top_level_images()` → 这是**多图容器**（连拍/多页），不是动画帧。
- ImageLoadThread 的 HEIF 分支**硬编码 `nFrameCount = 1; nFrameTimeMs = 0;`** 且 `WrapDecodedPixelsToImage(..., IF_HEIF, false, ...)` → `bHasAnimation` 恒为 false。
- 完全未引用 `heif_sequences.h` 的 API → HEIC 动画（image sequence / track）**不会播放**。

### libheif 1.23.1 可用 API（`libheif/include/libheif/heif_sequences.h`）
- `heif_context_has_sequence()` / `heif_context_get_sequence_timescale()` / `heif_context_get_sequence_duration()`
- `heif_context_number_of_sequence_tracks()` / `heif_context_get_track(ctx, 0)`（0 = 首个视觉轨道）
- `heif_track_decode_next_image(track, &img, cs, chroma, opts)` ← **顺序解码，无随机 seek**
- `heif_image_get_duration(img)`（track timescale）；`heif_track_get_number_of_repetitions()`；`heif_decoding_options::ignore_sequence_editlist`

## 若要做 HEIC 动画支持（评估，未实施）
- **主要难点：libheif 没有"总帧数"API**。`heif_context_get_sequence_duration()` 只给总时长。
  - 方案 A：首次顺序解码整段动画数帧 → 代价 = 完整解码一遍（比 JXL 的"只解帧头"扫描贵得多）。
  - 方案 B：用占位帧数（如 2）→ 会复现刚修掉的 JXL"只播前 2 帧"缺陷，不可取。
  - 方案 C：改动画推进机制为"顺序推进 + 遇 End_of_sequence 回绕"，不再依赖 `NumberOfFrames` 回绕 → 更正确，但要动 `Helpers::GetFrameIndex` 与调用的播放逻辑，影响面大。
- 还需：track 缓存（按顺序推进，不能随机帧索引）、帧时长换算、`bHasAnimation=true` 传递、EXIF/ICC 复用。
- 工作量：中等偏大；方案 C 会触及通用动画机制（所有格式共享），需谨慎回归。

每帧内容：中央大号帧号 + 背景色 = f(帧号)（r=(37i)%200, g=(91i)%200, b=(53i)%200）+ 底部黄色进度条长度随帧递增 → 三个维度交叉校验错帧。10 fps，一轮 3 秒。

生成方法：PowerShell + System.Drawing 画 30 张 PNG → ffmpeg 合成（脚本已删除）。
- **JXL 动画无法用本机 ffmpeg 生成**：有 `libjxl_anim` 编码器但**无 jxl muxer**（`-muxers` 里没有 jxl），只能出静态。
- **坑**：ffprobe/ffmpeg 探测动画 WebP 会报 `image data not found`（其 demuxer 局限，非文件损坏）；合法性用字节检查：动画 WebP 含 `ANIM`/`ANMF`、RIFF；APNG 含 `acTL`。AVIF 用 `ffprobe -show_entries stream=nb_frames` 会看到封面流 1 帧 + 动画流 30 帧两个 stream。

### 判读标准
- 数字 0→29 循环、颜色与进度条同步 → 无错帧。
- 数字跳号/回退、或数字与背景色不匹配 → 错帧。
- 数字不变/进度条不动 → 卡帧（解码器未推进）。
- 建议观察 ≥3 轮（约 10 秒），因为按机制分析若出错多在第二轮后（缓存交错）；并测试暂停/继续、"离开该图再回来"两类操作。
- GIF/AVIF 为随机访问模型，作对照：若它们也错，问题在播放框架而非格式解码器。

### 软件内的动画调速能力（代码结论）
- 动画播放节奏完全由文件帧时长驱动：`CMainDlg::StartAnimation()` → `SetTimer(ANIMATION_TIMER_EVENT_ID, max(10, m_pCurrentImage->FrameTimeMs()))`（`MainDlg.cpp:3651-3671`）。
- `CMainDlg::AdjustAnimationFrameTime()`（3673-3681）只做**解码耗时补偿**（把上一帧超时量从下一帧时长里扣除），不是调速。
- **JPEGView 没有动画速度倍数/调速设置**；数字键 1–9 属于 `StartMovieMode(dFPS)`（幻灯片/电影模式，跨图片播放，`MainDlg.cpp:1026-1034`、`3025+`），不作用于动画。
- 若要加"动画速度"控制：在 `StartAnimation`/`AdjustAnimationFrameTime` 的 `FrameTimeMs()` 上乘一个系数（0.25x/0.5x/2x 或固定毫秒），并配快捷键/INI 即可，约 30 行。
