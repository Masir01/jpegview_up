# 2026-10-06 "卡队列/翻不过去" bug 根因定位（代码级）

## 现象（用户报告）
- 状态栏显示 14/78，按"下一张"翻不过去；**能操作**（菜单可用、状态栏正常）、**有闪窗或蜂鸣**、End/Home 也无效、**只能重启程序**。
- 卡住的那张是 jpg/png 常见格式。

## 根因：文件列表迭代器被留在 `end()` 且无法恢复
链条（`src/JPEGView/FileList.cpp`）：
1. 删除当前图片时先 `GotoImage(POS_AwayFromCurrent, NO_REQUEST)` → `CFileList::AwayFromCurrent()`（FileList.cpp:496-509）：
   当 `sCurrentFile == NULL || sNextFile == NULL || 两者相等`（"only one image"）时执行 **`m_iter = m_fileList.end();`**（503 行）。
2. 删除成功后 `RemoveFile()`（FileList.cpp:360-389）：调用前 m_iter 已越界 → `sCurrentFile.IsEmpty()` → **`m_iter = m_fileList.end();`**（384 行，列表其实非空）；随后 `m_iterStart = m_bWrapAroundFolder ? m_iter : begin()`，wrap 默认 **true** → **`m_iterStart` 也越界**。
3. `CFileList::Next()`（417-455）开头：`if (iterTemp == m_fileList.end()) return this;` → **迭代器不动**，每次翻页都是 no-op。
4. `GotoImage()`（MainDlg.cpp:2618-2633）判定 `m_pFileList == pOldFileList && nOldFrameIndex == nFrameIndex && !ChangedSinceCheckpoint()` 成立 → **闪窗/蜂鸣 + return**，界面不重绘 → 状态栏停留在旧值（14/78）。
- `First()` 用 `m_iter = m_iterStart`（也越界）→ 无效；`Last()` 的 `MoveIterToLast()` 从 `end()` 出发 → 无效 → 只能重启。
- `ChangedSinceCheckpoint()` = `m_iterCheckPoint != m_iter`（FileList.h:128），纯迭代器位置比较；迭代器不动 → 恒为 false → 恒被挡住。

## 即时绕行（已验证逻辑）
按"上一张"（PageUp/←/滚轮上）：`Prev()` 在 `m_iter == m_iterStart`（end()==end()）且 wrap=true 时走 `m_iter--` → 拉回最后一张有效位置 → 位置变化 → 不再被"没换图"挡住。**"下一张"永远无效**（Next 缺兜底）。

## 建议修复（待用户确认）
1. `RemoveFile()` 越界分支改为 `m_iter = m_fileList.begin()`（列表非空即可用）。
2. 在 `Next()/Prev()/First()/Last()` 入口加 `EnsureValidIter()`：`m_iter`/`m_iterStart` 若停在 `end()` 则回到 `begin()`，实现自愈。

## 已实施修复（2026-10-06，`FileList.cpp` 4 处，均为内联兜底，未新增函数/未改头文件）
1. `RemoveFile()`（383-390）：`sCurrentFile.IsEmpty()` 分支由 `m_iter = m_fileList.end()` 改为 **`m_iter = m_fileList.begin()`**（消除越界状态源头）。
2. `Next()`：`if (m_iter == m_fileList.end()) { m_iter = m_fileList.begin(); return this; }`（原为 `iterTemp == end()` 时直接 `return this`，位置不动）。
3. `Prev()`：开头新增 `if (m_fileList.size() > 0 && m_iter == m_fileList.end()) { m_iter = m_fileList.end(); m_iter--; return this; }`（落到最后一张）。
4. `Last()`：`MoveIterToLast()` 前新增 `if (m_iter == m_fileList.end()) m_iter = m_fileList.begin();`。
- `First()` 无需改（本身即 `m_iter = m_iterStart = m_fileList.begin()`，天然自愈）。
- 关键语义：这些分支都**改变了迭代器位置**，因此 `ChangedSinceCheckpoint()`（`m_iterCheckPoint != m_iter`）会返回 true，`GotoImage` 不再走"没换到新图"的闪窗/蜂鸣 + return。
- 编译：Release|x64 exit=0，无 error C（仅既有 LNK4217 与 post-build MSB3073），exe 2026-10-06 01:16。
- 验证方式：打开含多图的目录 → 用删除功能删若干张（尤其是删到只剩最后一张时）→ 再翻页，应正常切换而不再卡死；即使出现越界，按"下一张"回到第一张、"上一张"回到最后一张。

## 日志实证 → 真正根因（2026-10-06 01:39–01:45，用户复测）
日志 494 行，决定性片段：
```
01:45:41.218  GotoImage pos=9 flags=1 size=50 idx=2 moved=1 cur=Z:\sdb\_FLJ_NF_ROSI\...\2021-04-14-4.jpg img=1
01:45:41.594  GotoImage pos=6 flags=0 size=49 idx=1 moved=0 ... img=0
01:45:41.594    -> load done img=1 err=0 oom=0 exc=0 idx=1
01:45:42.237  GotoImage pos=9 flags=1 size=0  idx=-1 moved=0 cur=<null> img=1        ← 列表被清空
01:45:42.237    -> SAME IMAGE, return (size=0 idx=-1 ... sameList=1 cur=<null>)
```
- `pos=9`=`POS_AwayFromCurrent`、`pos=6`=`POS_Current` → 正是**删除流程**；用户在 `Z:\sdb\...`（网络/映射盘）目录里连续删图，`size` 51→50→49→**0**。
- **真正根因**：目录监视器触发的**异步重扫在盘瞬时不可用/未就绪时返回空结果**，`OnScanCompleted()` 无条件 `m_fileList.swap(m_scanResult)` → 把 49 张的列表整个换成空列表。空列表下 `Next()` 无法移动迭代器（`begin()==end()`）→ `moved=0` → `GotoImage` 判定"没换图" → 闪窗 + return（状态栏保留旧文本）→ 永久卡死，只能重启。
- **上次"迭代器越界自愈"修复与此无关**（现象不是越界，而是列表变空）；那条修复保留（防御价值），但不足以解决本问题。

## 修复（2026-10-06 01:48 exe）
1. `FileList.cpp::OnScanCompleted()`：**扫描结果为空 + 旧列表非空 + 探测文件（当前文件，回退列表首项 `m_fileList.front()`）在磁盘上仍存在** → **不 swap，保留旧列表**，仅统一收尾（`m_bLoading=false`、关闭 cancel event、`m_hScanThread=NULL`）。只有文件真的消失（确实删空/移走）才接受空结果。
2. `MainDlg.cpp::GotoImage()`：在"没换图（SAME IMAGE）"判定命中时，**若 `m_pFileList->Size()==0 && !IsLoading()` 则触发一次异步 `Reload(NULL, false, m_hWnd)`** 以便自愈（Reload 异步、且不会重启进行中的扫描 → 不阻塞 UI）。
- 编译：Release x64 exit=0，exe **2026-10-06 01:48**。
- 诊断代码 `LogNav` 已按用户要求**宏化保留**（2026-10-06 02:10）：`MainDlg.cpp` 顶部 `#define NAV_DIAGNOSTICS 0`，函数本体与 3 处调用（GotoImage 入口、SAME IMAGE 判定、load done）全部用 `#if NAV_DIAGNOSTICS` 包裹。=1 时编译已验证通过（仅既有 C4090 警告）；=0 时诊断代码完全不进二进制（exe 5,972,480 vs 带日志时 5,977,600）。下次排查"翻不过去/卡住"类问题：把宏置 1 重编译即可，无需重新加代码。
