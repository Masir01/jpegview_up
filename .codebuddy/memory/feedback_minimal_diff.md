坚持"最小 diff"：**在当前配置下不可达**的健壮性/防御性改动，不要加进代码库。

**Why:** 2026-09-26 讨论上游 JPEGView_L 的 Fix #8（`TJPEGWrapper.cpp:170` 分配大小 `TJPAD(nScaledWidth * 3) * nScaledHeight` 的 int → size_t）时，用户先选择实施，在得知"该处溢出被 `MAX_IMAGE_PIXELS`（x64 524.3 Mpx）守卫挡住，触发需放宽守卫约 36.5%，当前行为零差异"后，选择回退并给出了"坚持最小 diff 原则"的理由。

**How to apply:**
- 采纳上游修复或自行加固前，先判断缺陷在**当前配置下是否可达**；不可达时明确说出"零行为差异"，让用户决定，**默认倾向不加**。
- 有可观察效果的修复仍正常实施（同日采纳的 Fix #21 文件大小显示小数即属此类）。
- 已实施且用户未要求回退的改动不要主动扩散式重构；改动本身保持最小、尽量贴合上游写法，便于日后同步上游。
